**The architecture, layer by layer** (the page has the pictures; this is the one-paragraph version)

Input `3×32×32` → **conv1** (16 stencils of 3×3, padding 1) `16×32×32` → **relu1** → **pool1** (2×2 max) `16×16×16` → **conv2** (32 stencils of 3×3×16) `32×16×16` → **relu2** → **pool2** `32×8×8` → **flatten** `2048` → **fc1** `128` → **relu3** → **dropout** (off) → **fc2** `10` scores → softmax to probabilities. 268,650 parameters, and the page's bottom table shows that 97.6% of them sit in `fc1` — that's the reason bigger CNNs replace the FC head with global pooling, which we can discuss when we go to option 1.

**Hyperparameters (all in `baseline.yaml`) and what each one does**

- `seed 42` — fixes weight initialisation and shuffling so a run is repeatable. Not the split seed; that's frozen in the CSVs.
- `batch_size 128` — images per gradient step. Larger = smoother gradient, fewer steps, more RAM.
- `normalize true` — subtract per-channel mean, divide by std, so inputs are centred around 0. Makes optimisation much better behaved. This is the change that will break the `[0,1]` assert in `verify_data.py`, as flagged.
- `random_crop_pad 4`, `horizontal_flip true` — augmentation, train only. Each epoch the model sees slightly shifted/mirrored versions, so it can't memorise pixel positions. Typically worth +3–5% on CIFAR.
- `conv_channels [16, 32]`, `fc_hidden 128` — model width. More channels = more patterns detectable = more params and time.
- `dropout 0.0` — off for the first run so we see raw behaviour; turn to 0.25–0.5 if val accuracy lags train (overfitting).
- `epochs 15` — full passes over the 45k training images. Tiny CNN should plateau around 10–15.
- `optimizer sgd`, `lr 0.05`, `momentum 0.9` — SGD with momentum is the CIFAR classic. `lr` is the step size: too high diverges, too low crawls. Momentum keeps velocity in a consistent direction. Alternative: Adam at lr 1e-3, easier to tune, slightly worse final accuracy on CNNs.
- `weight_decay 5e-4` — a small penalty on large weights (L2); a mild regulariser.
- `scheduler cosine` — the learning rate glides from 0.05 down to ~0 over the run. Big steps early, fine steps late. Alternative: step (drop ×10 at fixed epochs) or none.
- `early_stopping_patience 5` — stop if val accuracy hasn't improved for 5 epochs; always keep the best checkpoint.

**Evaluation methods we'll use to judge it**

- *Learning curves* — train loss and val loss/accuracy per epoch on one plot. The shape is the diagnosis: both falling together = learning; train falling while val rises = overfitting; both flat and high = underfitting or lr wrong.
- *Confusion matrix* — 10×10 grid of true class vs predicted class on val. The diagonal is correct; off-diagonal cells show *which* mistakes: cat↔dog and automobile↔truck are the classic CIFAR confusions.
- *Per-class accuracy / precision / recall / F1* — overall accuracy hides that a model can be great on ships and terrible on birds.
- *Top-k accuracy* (top-2) — was the right answer at least second? Useful for "nearly right".
- *Calibration* — when the model says 90% confident, is it right 90% of the time? A reliability diagram shows this; cheap to add.
- *Worst-mistake gallery* — the val images it got wrong with the highest confidence. The most instructive plot there is, and matches your "see it with my eyes" style.
- *Final test-set accuracy* — run exactly once, at the end, on the sealed 10k.
